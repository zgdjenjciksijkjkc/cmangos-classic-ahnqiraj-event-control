# CMaNGOS Classic 安其拉事件恢复与控制工具

[English](README.md)

这是一个面向 Windows 版 [CMaNGOS Classic](https://github.com/cmangos/mangos-classic)
的安其拉内容恢复包，包含我们目前已经完成并实测的全部成果：事件 120–123 阶段
控制、甲虫之墙关闭/开放、原始十小时战争，以及荣誉徽章声望和物资箱任务修复。

> 本版暂时不修复或重建安其拉开门任务链，不修改任务 8743，也不补全流沙节杖
> 任务链。这部分会在后续版本继续研究。

## 已包含的修复

### 事件 120–123 与甲虫之墙

| 菜单 | 核心阶段 | 事件 | 大门 | 行为 |
|---|---:|---:|---|---|
| 物资收集 | 1 | 120 | 关闭 | 清零全部 30 项物资计数 |
| 物资运输 | 2 | 121 | 关闭 | 保留计数并手动锁定，不自动推进 |
| 等待敲锣 | 3 | 122 | 关闭 | 进入服务器已有的敲锣前阶段 |
| 十小时战争 | 4 | 123 | 开放 | 到期时间为数据库当前时间加 36000 秒 |
| 关闭全部 | 0 | — | 开放 | 关闭战争物资核心开关 |

控制器会：

- 把事件 120–127 恢复为服务器控制类型 `schedule_type = 0`；
- 将实测可用的关门对象 `49390–49392` 绑定到事件 120、121、122；
- 校验并更新 `classiccharacters.world_state.Id = 1` 的 35 个数字字段；
- 清除旧 AQ 持久事件记录，让核心根据 WorldState 选择新阶段；
- 启用阶段时设置 `WarEffort.Enable = 1`，并恢复 `WarEffort.Rates = 1`；
- 使用世界库已有的事件 123 军队和共鸣水晶，不制造重复生成；
- 修改前自动备份数据库行和配置文件。

`WarEffort.Rates = 1` 表示恢复 CMaNGOS 的原始物资目标，并不表示每种物资都
精确需要 5000，因为原版各物资的基准数量并不完全相同。

- 联盟任务 `8846–8850` 恢复到大元帅斯诺·落雪（`15701`）。
- 部落任务 `8851–8855` 恢复到督军格尔库克（`15700`）。
- 10 个任务全部可重复，并补齐开始和完成关系。
- 保留原有徽章消耗与奖励箱 `21509–21513`。

### Windows/MySQL 中文编码修复

脚本不再通过 Windows 控制台代码页把中文 SQL 直接送入 `mysql.exe`，而是使用
一次性的无 BOM UTF-8 文件，从而修复实测的 `ERROR 1366`，不要求 PowerShell 7，
也不修改 `mangosd.exe`。

## 暂时不包含

- 不修复或重建完整安其拉开门/流沙节杖任务链。
- 不写入任务 8743；对任务 8743 和广播 11427/11432 只有只读检查。
- 不保证所有 CMaNGOS 分支完成敲锣后都能自动从 122 进入 123。
- 不修复萨鲁法尔行军/演讲、完整过场、门体原生动画或声音。
- 不包含服务端可执行文件、核心二进制补丁、客户端数据、数据库转储或密码。

实测 Larmer Build 原本就能在完成任务 8743 后从 122 进入 123；这是该核心已有
行为，不是本包提供的任务链修复。需要绕过任务逻辑时，可停服后使用菜单 4 直接
进入事件 123。`source` 目录只是整体禁用的历史研究资料，不会被安装、编译，
也不是运行本包所必需的文件。

## 兼容条件

本版面向以下 Windows CMaNGOS Classic / WoW 1.12.x 环境：

- 数据库名为 `classicmangos` 和 `classiccharacters`；
- 服务端根目录含 `mangosd.conf`；
- 含 `mysql5\bin\mysql.exe`、`mysqldump.exe` 和 `mysqld.exe`；
- 世界库已有事件 120–123 和相应门体；
- `classiccharacters.world_state.Id = 1` 是 35 个数字字段；
- 任务表与 NPC 关系表符合本包验证过的 CMaNGOS Classic 结构。

不同整合端可能改变数据库结构、GUID 或核心行为。脚本会在修改前验证必要表、
字段、任务和数量，不符合预期时停止。

## 安装

1. 备份世界库、角色库、服务端目录和 `mangosd.conf`。
2. 将完整发布包复制到服务端根目录，不要漏掉 `sql` 目录。
3. 正常停止 `mangosd`；MySQL 可以保持运行。
4. 双击 `AQ事件控制.bat`，选择菜单 1–4 中的目标阶段。
5. 启动 `mangosd`，在控制台执行 `event list`，并用菜单 5 查看数据库状态。

菜单 1–4 会先幂等安装徽章任务修复，再切换阶段。菜单 6 只关闭 AQ 事件，
不会撤销内容修复。独立 SQL 包括：

- `sql/01_apply_world_data.sql`：静态 AQ 事件与关门数据；
- `sql/02_rollback_world_data.sql`：静态 AQ 数据回滚；
- `sql/03_apply_commendation_fix.sql`：徽章声望与物资箱任务修复；
- `sql/04_verify_commendation_fix.sql`：只读校验；
- `sql/05_rollback_commendation_fix.sql`：首次独立安装前内容回滚。

## 备份和验收

每次修改前会在 `autobak\AQ事件控制` 建立自动备份。状态页应显示：

- 主城声望任务 `32/32` 正确；
- 物资箱任务 `10/10` 可重复、`10/10` 可交付；
- WorldState 字段 `35/35`；
- 三个关门对象分别绑定 `120,121,122`；
- 选择阶段 4 后事件 123 激活、大门可通过。

实测目标表为 MyISAM，无法依赖事务回滚。因此脚本会先生成精确的
`AQ_commendation_rollback_*.sql`，应用后再校验；校验失败则自动恢复并停止切换。
