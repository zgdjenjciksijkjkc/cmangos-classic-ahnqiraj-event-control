CMaNGOS Classic 1.12 安其拉事件控制与徽章任务修复包
版本：v1.0.0 / 2026-08-24

【公开版范围】

本包包含目前已经完成并实测的全部成果：

- 安其拉事件 120、121、122、123 的手动阶段切换；
- 事件 120-122 的甲虫之墙关闭门体与碰撞；
- 事件 123 的开门状态、已有入侵军队与原始十小时战争计时；
- WarEffort.Enable 与 WarEffort.Rates 的安全配置修改；
- 荣誉徽章主城声望任务 8811-8845 修复；
- 大元帅斯诺·落雪/督军格尔库克物资箱任务 8846-8855 修复；
- 自动备份、状态校验、独立安装 SQL 与回滚 SQL。

本包暂时不包含安其拉开门任务链修复。它不会创建或补全流沙节杖任务链，
不会修改任务 8743，也不会保证所有 CMaNGOS 分支都能在完成敲锣任务后自动从
事件 122 切换到事件 123。菜单 3 只进入服务器已有的等待敲锣阶段；菜单 4 可在
停服后直接进入事件 123。脚本对任务 8743 和广播 11427/11432 只有只读状态检查。

source 目录只是已禁用的历史研究草案，不会被脚本安装或编译，也不是开门任务链
修复。后续版本会继续研究任务链、广播、门体动画和剧情表现。

【2026-08-24 事件 123 原始时长恢复】

菜单 4 已移除“15 分钟后跨入最后一小时”的加速诊断模式，恢复为完整的十小时
战争。脚本把事件 123 到期时间设置为数据库当前时间加 36000 秒。

【2026-08-24 战争物资倍率修复】

本版在菜单 1-4 启用 AQ 阶段时，自动将 mangosd.conf 中的
WarEffort.Rates 设置为 1，恢复 CMaNGOS 原始战争物资需求量。旧配置 0.001 会把
所有目标缩小到千分之一，因此只需少量捐献便会完成。

注意：Rates 是统一倍率，原版各物资的基准目标并不相同；设置为 1 表示恢复原始
需求量，并不表示每一种物资都精确需要 5000。脚本只替换倍率数值对应的 ASCII
字节，保留配置文件的原编码、中文内容和换行格式，并在 autobak\AQ事件控制 下
生成 mangosd.conf_rate_*.bak。菜单 5 会同时显示 WarEffort.Enable 和
WarEffort.Rates；菜单 6 不会把倍率改回 0.001。

【2026-08-12 荣誉徽章修复版新增说明】

【v2 编码修复】

修复 Windows PowerShell 通过标准输入调用 mysql.exe 时把中文 SQL 按系统代码页
发送、而 MySQL 按 UTF-8 解码所导致的 ERROR 1366。脚本现在将每条 SQL 写入一次性
无 BOM UTF-8 临时文件，交给 mysql.exe 原生读取，并在执行后立即删除；校验与安装
临时表也显式使用 UTF-8。此实现兼容本端的 Windows PowerShell 5.1，不依赖较新的
StandardInputEncoding 属性。本修复发生在任务数据写入之前，不涉及 mangosd.exe
或角色库。

本版新增世界数据库内容修复：

- 32 个主城声望兑换任务恢复正确城市、声望和前后继关系；
- 1 枚荣誉徽章奖励 5 点对应主城声望，10 枚奖励 75 点；
- 铁炉堡/奥格瑞玛物资区嘉奖官和八位主城军官都可完成相应首次任务；

安装时必须复制本包全部内容，尤其不能漏掉 sql 目录中的 03、04、05 文件。

目标表是 MyISAM，不支持事务回滚。因此脚本先在

状态页新增：

- 主城声望任务：32/32 正确；
- 物资箱兑换任务：10/10 可重复，10/10 可交付；
- 校验失败时显示具体错误任务 ID。

独立 SQL：

- sql\03_apply_commendation_fix.sql：幂等安装并创建 aq_backup_20260812_* 表；
- sql\04_verify_commendation_fix.sql：只读校验；
- sql\05_rollback_commendation_fix.sql：恢复首次独立安装前的数据。

本版不修改 mangosd.exe、核心源码和角色数据，也不会补发以往消耗的徽章或声望。

一、已经实测通过的流程

1. 事件 120：物资收集，大门关闭并有碰撞。
2. 事件 121：物资运输，手动锁定，大门保持关闭。
3. 事件 122：等待敲锣，任务 8743 可完成，大门保持关闭。
4. 完成任务 8743 后，本机 Larmer Build 会自动：
   - 把核心阶段切换为 4；
   - 停止事件 122，激活事件 123；
   - 移除只绑定于 120-122 的关门组，大门完全开放且可通过；
   - 启动十小时战争计时；
   - 生成数据库已有的入侵军队和其拉共鸣水晶；
   - 发送广播 11432。

本次实测中没有出现含玩家名的广播 11427，也没有播放符文、树根和主门的
开启动画或声音。这两项属于视觉/广播完整度，不影响开门、碰撞移除和事件 123。

二、重要的世界状态结论

classiccharacters.world_state.Id=1 必须包含 35 个数字字段。

- 第 1 字段：AQ 核心阶段。
- 第 2 字段：在事件 123 中是 Unix 到期时间戳（秒），不是毫秒时长。
- 第 33 字段：运输物资层级。
- 第 35 字段：此 Larmer Build 中用途尚未确认。

实测开门成功后第 35 字段仍然为 0，因此控制脚本不再修改它，也不再用它判断
大门状态。大门状态由核心阶段和 GUID 49390-49392 的事件绑定关系推断：

- 阶段 1-3 / 事件 120-122：关门组生成，大门关闭。
- 阶段 4 / 事件 123：关门组不生成，大门开放。

三、安装

1. 正常关闭 mangosd。
2. 备份服务端根目录。
3. 将本包全部内容复制到服务端根目录并覆盖旧版（不要漏掉 sql 目录）：
   AQ事件控制.bat
   AQ事件控制.ps1
   aq_event_control_launcher.ps1
4. 三个文件必须和 mangosd.conf、mysql5 目录位于同一层。
5. 双击 AQ事件控制.bat。

菜单说明：

1. Event 120 - Collection
2. Event 121 - Transportation
3. Event 122 - Gong ready
4. Event 123 - Original 10-hour war
5. Status
6. Disable AQ events
0. Exit

菜单 1、2、3、4、6 必须在 mangosd 停止时使用。菜单 5 是只读检查，mangosd
运行时也可使用。脚本以单字节方式修改 WarEffort.Enable，不会改写配置文件的
编码或换行。

四、事件 123 原始十小时战争

菜单 4 用于直接进入事件 123，并恢复 CMaNGOS 原始的十小时战争持续时间：

1. 脚本先备份 world_state.Id=1、game_event_status 及相关世界库行。
2. 把 AQ 核心阶段设置为 4（事件 123）。
3. 使用 MySQL 自己的 UNIX_TIMESTAMP() 作为当前时间来源。
4. 把事件 123 到期时间设置为当前时间加 36000 秒，即完整 10 小时。
5. 启动 mangosd 后由核心激活事件 123、生成军队并按正常速度推进战争。

此操作不会修改 mangosd.exe，也不会修改 Windows 系统时间。需要重新开始十小时
战争时，先正常关闭 mangosd，再执行菜单 4；不要在 mangosd 运行时直接修改
world_state。

五、状态页说明

状态页会显示：

- 主城声望兑换任务是否 32/32 正确；
- 物资箱兑换任务是否 10/10 可重复、10/10 可交付；
- 角色库持久事件记录；
- 35 字段完整性、核心阶段和本地时间的战争到期/剩余时间；
- 按阶段与事件绑定推断的大门状态；
- 第 35 字段原值，但不会宣称它是 GatesOpen；
- 关门组 GUID 49390-49392 的模板、生成状态和事件绑定；
- 事件 123 的生物与游戏物体数量；
- 任务 8743、广播 11427/11432 数据；
- mangosd.exe 的 SHA256 及是否为已实测构建。

角色库 game_event_status 只是持久记录。mangosd 正在运行时，服务器内存中的
实际事件仍以服务器控制台 event list 为准。

六、数据库 SQL

sql\01_apply_world_data.sql：

- 要求 mangosd 已停止；
- 备份受影响的 AQ 事件和门体行；
- 恢复 120-127 为核心控制；
- 把 GUID 49390-49392 绑定到 120、121、122；
- 不创建或复制事件 123 军队。

sql\02_rollback_world_data.sql 会从 aq_backup_20260804_* 表恢复静态数据。
日常切换阶段时，菜单 1-3 会自动应用相同门体配置，无须重复执行 SQL。

七、事件 123 数据基线

当前 classicmangos 数据库实测：

- 正向生物：726
- 负向移除生物：96
- 正向游戏物体：41

状态页会实时查询数据库，不会硬编码这些数字冒充运行时结果。游戏内仍应以
event list、实际生成物和服务器日志共同验收。

八、可选源码资料

source 目录中的 C++ 文件只是已归档、禁用编译的研究草案，不是本包运行所需
补丁。现有 Larmer Build 已经能够完成开门并进入事件 123，不应为了追求十秒
过渡、11427 或原生动画而直接套用该草案。只有取得完全匹配的源码、确认各字段
真实语义并单独建立测试环境时，才可重新设计这些可选表现。

九、回退

1. 每次脚本切换阶段前的自动备份：
   <服务端根目录>\autobak\AQ事件控制
2. 静态 SQL 回退：sql\02_rollback_world_data.sql
3. 徽章任务自动回退：最近的 AQ_commendation_rollback_*.sql
4. 独立 SQL 回退：sql\05_rollback_commendation_fix.sql
5. 本包没有替换 mangosd.exe，不需要二进制回退。
